# «Рыцарь одного дня» — первый играбельный прототип (дистанционный бой)

Структуру петли берём из «The Knight Only Lives Today» / «오늘만 사는 기사» —
только структуру (день = забег, замок = урок, ступень = глагол). Сюжет, имена
и сцены — свои; авторитетный документ решений — [`design.md`](design.md).

## Контракт хода

Раунд боя (`run_combat()` в `combat.lvns`) — строго:

1. **Ход игрока** (`player_turn()`) — один пункт меню:
   - ⚔ **Взмах мечом** — базовый глагол ступени 0. Попадает только на `distance == 1`.
   - 🛡 **Блок** — гасит одно ближайшее/дальнее попадание врага в этом раунде.
   - ▶ **Шаг вперёд** / ◀ **Шаг назад** — `distance ∓ 1`, зажато в `1..9`.
   - Скрытые до открытия ступени (см. «Будущие глаголы» ниже).
2. Если `enemy_hp <= 0` после хода игрока — бой заканчивается `"win"`, ход
   врага не разыгрывается (добивать самого себя враг не может по определению).
3. **Ход врага** (`enemy_take_turn()`) — детерминированный, по профилю
   `enemy_ai` (таблицы ниже). Никакого `rand()`/`chance()`.
4. Если `hp <= 0` — `"dead"`. Если раунд достиг `combat_max_rounds` (20) без
   исхода — `"timeout"` (явный обрыв, не soft-lock).
5. Иначе — раунд `+1`, назад к шагу 1.

Между раундами перерисовываются и противник (крупнее/мельче по трём зонам
дистанции — 1..3/4..6/7..9, три позы: idle/attack/hurt), и руки героя внизу
экрана (idle/attack/block) — обе через `obj id=... sprite_url=...`, не через
`actor` (у противника нет записи в манифесте кастинга, и не должно быть —
это не персонаж, а сборный спрайт, см. `howto/LANGUAGE.md` §8).

## Таблица решений трёх ИИ-профилей

`.lvns` не даёт настоящих структур/массивов объектов, поэтому "data-driven"
здесь означает: один профиль — одна ветка в `enemy_take_turn()`, новый враг
того же профиля просто выставляет другие числа (`enemy_atk`,
`enemy_pref_range`), не новый код.

| Профиль | Условие | Действие |
|---|---|---|
| `aggressive_melee` (скелет v1) | `distance <= 1` | Бьёт (или бьётся в блок). |
| | `distance > 1` | Шаг вперёд. |
| `cautious_melee` (задел, не используется в v1) | фаза 0/1, `distance < 2` | Отступает. |
| | фаза 0/1, `distance >= 2` | Выжидает, не раскрываясь. |
| | фаза 2 (любая дистанция) | Рывок на `distance = 1`, бьёт. Фаза → 0. |
| `ranged` (задел, не используется в v1) | `distance < preferred_range` | Отходит. |
| | `distance > preferred_range` | Приближается. |
| | `distance == preferred_range` | Стреляет (первый выстрел — см. `global.step_first_shot_block`). |

`cautious_melee` и `ranged` — рабочий код, не заглушки: если завтра design.md
опишет второй замок с одним из этих профилей, глава просто выставит
`enemy_ai = "cautious_melee"` (и т.д.) — ветка уже готова и уже проверяется
компилятором (иначе валидатор пометил бы её как мёртвую метку).

## Как включаются будущие глаголы

Design.md называет четыре будущих глагола, но ещё не приписал им ступень в
лестнице (§2 там — прочерки). Они уже вписаны в `combat.lvns` как **рабочие,
но недостижимые в v1** ветки:

| Переменная | Глагол | Где висит условие |
|---|---|---|
| `global.step_jump` | Длинный шаг (2 клетки) | `expr=` пункта меню в `player_turn()` |
| `global.step_dual` | Двойной удар (два взмаха за ход) | там же |
| `global.step_throw` | Бросок (дальний урон) | там же, вдобавок `run_throw_charges >= 1` — заготовка под инвентарь забега, которого ещё нет |
| `global.step_first_shot_block` | Пассивный блок первого дальнего выстрела | внутри `ai_ranged` в `enemy_take_turn()` |

Ни одна из этих переменных **не присваивается** ни в `ch01.lvns`, ни в
`combat.lvns` — они только читаются. Открыть ступень значит начать её
присваивать (`inc key="global.step_jump" by=1` и т.п.) в НОВОМ месте — там,
где design.md сочтёт нужным (конец конкретного боя-урока), не здесь и не
самовольно.

Новый глагол ступени N добавляется тем же способом: одна строка меню с
`expr="global.step_N >= 1"` + одна ветка разрешения в `player_turn()`
(и, если нужно, в `enemy_take_turn()` — как `first_shot_block`, который не
даёт герою собственного действия, а меняет исход чужого).

## Как работает петля дня

```
:day_start
день += 1, hp = maxhp, distance = rand(3,7)   // подход разный, замок один и тот же (П2)
enemy_* = фиксированные числа скелета «Низший» // не растут вслед за игроком
run_combat()
  win     -> :day_victory  -> __end (см. «Ограничения v1» — почему не открывает ступень)
  dead    -> :day_death    -> :day_start
  timeout -> :day_timeout  -> :day_start
```

`global.step_*` пережили бы день/смерть автоматически (это read-only-часть
глобального персистентного блоба движка) — но в этой сборке их некому
записать, поэтому первый прототип **не демонстрирует** межднёвный прогресс
сам по себе, только гарантирует, что механика для него готова.

## Проверка

```sh
# сборка транскодера
cd tools/lvnconv && go build -o /tmp/lvnconv .

# компиляция + валидация (ch01.lvns подключает combat.lvns через include)
cd ../..
/tmp/lvnconv convert  -i content/knight-roguelike/ch01.lvns -o /tmp/kr.lvn
/tmp/lvnconv validate /tmp/kr.lvn
/tmp/lvnconv probe    /tmp/kr.lvn
```

Результат на момент коммита:

```
OK: 335 command(s), 0 warning(s)
scene=knight-roguelike-ch01 commands=335 say=27 choice=1 label=103 goto=59 if=36 bg=0 actor=0
```

Два детерминированных прохождения проверены headless-плеером плейграунда
(`server/website/play/core.js` — тот же чистый JS-порт `LvnPlayer`, без DOM,
используется для эту разовую проверку, не как новый тестовый фреймворк):

- **Всегда «Взмах»** — герой сближается, пока враг сам идёт навстречу, и
  добивает его за 8 раундов: `combat_outcome = "win"`, герой выживает с 1♥.
- **Всегда «Шаг вперёд», ни разу не бьёт** — сближается, но никогда не
  атакует и не блокирует: гибнет на 4-м раунде от двух ударов подряд,
  `combat_outcome = "dead"`, петля дня корректно уходит на `:day_start`
  (в проверке — 500 шагов, десятки повторов дня, ни одного зависания).

## Ограничения первой версии (честно)

- **Размер противника — 3 зоны, не 9 отдельных дистанций.** Движок не умеет
  привязывать числовые поля `obj`/`actor` (`width`/`height`) к выражению —
  только литералы (проверено на компиляторе, `tools/lvnconv/internal/lvns`).
  Отсюда — таблица зон, а не honest-9-branch версия из ТЗ; см. комментарий в
  `render_enemy()`.
- **Победа не открывает ступень 1.** Design.md §2 оставляет глагол ступени 1
  прочерком («?») — открывать нечего, пока дизайн не решит, что это. На месте
  разблокировки — явный `TODO` в `:day_victory` (`ch01.lvns`).
- **`throw`/`dual`/`jump` — работающий код без пути включения.** Экономика
  предметов забега (для `бросок`) не описана нигде дальше одной строки ТЗ —
  `run_throw_charges` объявлен, но ничем не пополняется; ветка недостижима
  игроком за счёт `expr=`, но не удалена, чтобы не переписывать её вдвойне,
  когда инвентарь появится.
- **`cautious_melee` и `ranged` не сыграны ни разу.** Код существует и
  компилируется (иначе — мёртвая метка), но без второго замка его некому
  вызвать. Первая проверка настоящим боем — при первом реальном противнике.
  Хук на будущее закреплён комментарием прямо в `enemy_take_turn()`.
- **Нет фона.** Только крупный план врага + руки — художники ещё не прислали
  список фоновых ассетов, и придумывать путь самовольно рискованно (можно
  разойтись с их манифестом). `bg` добавляется одной строкой в `ch01.lvns`,
  когда путь появится.
- **HP предельно мал (2/2 у обеих сторон)** — по ТЗ: «не хп-губка, 1–2 точных
  удара максимум». Это буквально означает, что почти любая ошибка на
  дистанции 1 стоит половины здоровья — раздувать эти числа при добавлении
  второго замка не нужно, сама механика уже проверяет тайминг, а не сумму
  статов.
