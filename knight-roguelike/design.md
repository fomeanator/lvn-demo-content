## 1. Ядро: почему этот референс — уже роглайк

Герой референса погибает и просыпается в начале того же дня. Никакой выданной
«системы» у него нет — только бесконечные попытки и собственный труд.

Отсюда три принципа, на которых стоит вся игра:

**П1. День = забег.** Смерть не наказание, а рестарт петли. Игрок теряет
предметы и позицию, но не теряет *понимание*.

**П2. Враг не растёт — растёт игрок.** Классический роглайк повышает цифры
врага по мере глубины. Мы делаем наоборот: противник на ступени фиксирован и
неизменен. Ощущение «плавности», которое зацепило в референсе, берётся именно
отсюда — прогресс измеряется тем, что вчера непроходимая стена сегодня
проходится.

**П3. Прогресс — это новый глагол, а не новое число.** Каждая ступень даёт не
+10% урона, а новое *действие*, которое переписывает уже виденные ситуации.
Взмах → удержание строя → бросок. Старая комната с новым глаголом — новая комната.

## 2. Лестница ступеней ↔ противник-замок

Главная таблица дока. Читается так: ступень героя открывает глагол; напротив
стоит противник, который **специально** сконструирован так, что без этого
глагола непроходим, а с ним — честно проходим.

Противник = замок. Глагол = ключ. Игрок сам понимает, какой ключ ему нужен.

| # | Ступень героя | Новый глагол | Противник-замок | Чем ломает без глагола |
|---|---------------|--------------|-----------------|------------------------|
| 0 | Никто | `взмах` | *(манекен / первый враг)* | — обучение петле |
| 1 | Держит меч | ? | ? | ? |
| 2 | Тело | ? | ? | ? |
| 3 | Дистанция (метание) | `бросок` | ? | ? |
| 4 | ? | ? | ? | ? |
| 5 | ? | ? | ? | ? |
| 6 | ? | ? | ? | ? |

### Правило проверки ступени

Ступень засчитана, только если выполняются оба:

1. её можно объяснить одной фразой в императиве («бросай, не подходи»);
2. существует ровно один противник, который без неё не проходится.

Если ступень не проходит проверку — это не ступень, а пассивный бафф.
Пассивные баффы идут в мета-слой (§4), в лестницу не лезут.

## 3. Ранги — шкала мира, а не шкала игрока

В референсе есть внешняя система рангов рыцарей (ступени Base → High).
Нам она нужна не для прокачки, а как **язык, которым мир говорит об опасности**.

Ранг — это ярлык на противнике, читаемый до боя. Игрок видит ранг и заранее
знает: «это выше меня на две ступени, сюда рано». Ранг ничего не считает
механически — он честно предупреждает.

```
ранг_врага - ступень_героя = дистанция
  <= 0  — проходится уверенно
   = 1  — проходится на грани, ценой ресурса
   = 2  — проходится только идеально, редко
  >= 3  — не проходится, и игра этого не скрывает
```

Это даёт роглайк-жадность без случайных смертей: игрок сам выбирает, лезть ли
на дистанцию 2, и смерть там — его решение, а не подстава генератора.

## 4. Два слоя прогрессии

**Внутри дня (сгорает при смерти):** раны, снаряжение, союзники, позиция,
время суток. Всё, что делает конкретный забег уникальным.

**Между днями (остаётся навсегда):** ступени из §2. И только они.

Отдельно — третий, самый важный слой:

**Знание игрока (не хранится нигде).** Игрок узнаёт, что у этого противника
предсказуемый первый выпад. Движок об этом не знает и хранить не должен —
но диалоговые опции пишем так, чтобы знающий игрок видел в них смысл, которого
не видел в первый раз. Это лучший вид роглайк-прогрессии и стоит он ноль.

## 5. Как ложится на движок

Всё нужное в движке уже есть — см. рабочий пример `howto/roguelike/roguelike.lvns`.

**Ступени — обычные переменные, персистентные между забегами.** Глобальные статы
живут в `global.*` и переживают рестарт новеллы:

```
global.step_sword = 0
global.step_body  = 0
global.step_throw = 0
```

**Глагол как опция с условием.** Ступень буквально добавляет игроку строку
выбора — тот самый «новый глагол»:

```
- 🗡 Рубить с замаха     -> swing
- 🪨 Метнуть камень      -> throw  expr="global.step_throw >= 1"
```

Игрок, не открывший ступень, опции не видит. Открывший — видит, и старая сцена
читается иначе. Это П3 в одну строку.

**Противник-замок — порог, а не хп-губка.** Не «много здоровья», а прямая
проверка ключа:

```
:gatekeeper
if global.step_throw < 1 -> gk_wall   // без броска — стена
-> gk_open
```

**Петля дня — метка + прыжок**, как `:descend` в примере:

```
:day_start
day = day + 1
...
if hp <= 0 -> death
:death
// ступени НЕ трогаем — они переживают смерть
-> day_start
```

**HUD** — одна реактивная строка, сама обновляется по переменным:

```
text hud x=3 y=8 size=42 «День {day}  ♥{hp}/{maxhp}  ступень {rank_name}»
```

**Случайность — на приправу, не на скелет.** `rand`/`chance` крутим на мелочах
(кто первый ударил, повезло ли с погодой), но НЕ на том, проходим ли замок.
Замок должен быть детерминирован, иначе П2 разваливается.

## 6.5. Боёвка v2 — дуэль-инкрементор (решение владельца, 2026-07-31)

Дистанционный бой (`combat.lvns`) остаётся как v1; направление сменено на
**инкрементор** (`duel.lvns` + песочница `duel-ch01.lvns`):

- **Очередь растёт.** Обмен 1 — планируешь 1 действие, обмен 2 — два, и так
  до капа 5. Оба планируют вслепую (враг — по паттерну), потом очередь
  прокручивается такт за тактом. Эскалация глубины планирования = драматургия
  боя; аналогов механики не нашли (ближайшие родственники: Frozen Synapse,
  Toribash, Punch Club, покемоны — но растущей очереди нет ни у кого).
- **Матрица такта + темп.** удар×удар — размен (у кого темп больше, бьёт
  первым на 2, темп сгорает); удар×блок — защитник копит +1 темп; блок×блок —
  пусто. Блок — инвестиция, не трусость; вечный блок не выигрывает, вечный
  удар кормит чужой банк → играть приходится по паттерну.
- **Паттерн вместо рандома** (наследие П2 и модели Punch-Out): тычок
  подсказывает только ПЕРВЫЙ такт обмена, остальное — память игрока. Паттерн
  не сбрасывается между обменами. На половине хп враг «звереет» — вторая
  строфа паттерна, объявляется явно.
- **Навыки занимают такт очереди** и открываются озарением — развилка всегда
  из ДВУХ (💫 оглушение против его удара за темп / 🔨 пробив сквозь его блок с
  риском). Владение в %: опыт по заслугам — молоко +1, эффект +3, крит +6;
  ступень = 1 + floor(влад/25), каждая ступень меняет числа (как грейды в
  доте), не «+урон».
- **Проверено симуляцией** (матрица 1:1 с `resolve_beat`): наивный «только
  удар» падает на 3-м обмене; «только блок» — ничья без победы; читающий
  паттерн без навыков побеждает 5-м обменом с ♥3; с любым навыком — без
  потерь. Ровно та кривая «вчера стена — сегодня проходится».

Открытое: дизайн IV ступени навыков, темп роста владения (пробив добегает до
II ступени за один бой), нужен ли журнал последних обменов как опция
доступности.
